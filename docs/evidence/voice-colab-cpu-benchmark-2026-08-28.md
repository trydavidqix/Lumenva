## Result

- faster-whisper worked on CPU and stayed below real time in all runs.
- Piper worked on CPU, but synthesis latency was 2.44–3.66 seconds for roughly 3.8 seconds of audio; this is marginal for interactive voice.
- Kokoro worked on CPU after switching to Python 3.12, but remained slower than real time in every run and had a 7.91-second model-load cost.
- A sequential STT+TTS loop is not within the desired 1–2-second interactive budget on this CPU runtime.
- Do not spend on another small 2-CPU/3.7-GB VPS expecting real-time voice. If real-time voice is required, test a stronger fixed CPU or GPU host and benchmark streaming/parallel execution separately.

No VPS or production credentials were used.

## Validation method

- Runtime selected from Colab `Ambiente de execução → Alterar o tipo de ambiente de execução`:
  CPU and runtime `2026.07` (Python `3.12.13`).
- Packages installed inside the ephemeral runtime with `python -m pip`: `faster-whisper`,
  `piper-tts`, `kokoro==0.9.4`, `soundfile`; system dependency `espeak-ng` installed with apt.
- Piper model downloaded with `python -m piper.download_voices --data-dir /content/piper-voices
  pt_BR-cadu-medium`.
- The ~10-second input was generated by Piper from a fixed Portuguese text and measured with
  `soundfile.info(...).duration`.
- STT timing used `WhisperModel('tiny', device='cpu', compute_type='int8', cpu_threads=2)` and
  materialized all transcription segments with `list(segments)` before stopping the timer.
- Kokoro timing used `KPipeline(lang_code='p', device='cpu')` and materialized all generated
  chunks before stopping the timer.
- Each engine was run three times. Raw values are preserved above; real-time factor is
  `elapsed_seconds / audio_duration_seconds`.
- Validation was isolated to the Colab runtime. No Asterisk, Pipecat worker, SIP trunk, PSTN call,
  production credential or `VOICE_LIVE_ENABLED=true` was used.
