# AI Platform Phase 7 — LangGraph Proposal Approval Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove LangGraph on one bounded workflow — generating a commercial proposal draft, pausing for manager approval/edit/reject, resuming safely, sending exactly once through the existing channel path, and scheduling follow-up.

**Architecture:** The normal agent runtime remains unchanged. LangGraph is invoked only for explicit `commercial_proposal` workflow runs and only for tenants enabled by feature flag. CRM PostgreSQL stores the official workflow registry/decision; LangGraph Postgres checkpointer stores resumable execution state in a separate internal schema. Side effects use stable idempotency keys so resume/retry cannot send twice.

**Tech Stack:** TypeScript, `@langchain/langgraph`, `@langchain/langgraph-checkpoint-postgres`, `pg`, existing agent LLM seam, existing WAHA/channel adapter and follow-up scheduling paths, Supabase/Postgres, Next.js API/UI, Vitest, Playwright.

## Global Constraints

- Phase 6 gate must be `GO` or `GO` with n8n intentionally OFF.
- LangGraph is never used for every inbound WhatsApp turn.
- Feature starts `OFF`; `SHADOW` can generate/evaluate drafts but must not send or require real human approval.
- `thread_id` is generated by server and bound to a tenant workflow row; never accepted as user/model authority.
- Workflow state never replaces CRM lead/contact/conversation state.
- No side effect may run twice after interrupt/resume/retry.
- Any payment/contract acceptance remains outside this pilot.
